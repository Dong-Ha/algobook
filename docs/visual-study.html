01 / BOUNDARY SEARCH

최소 용량은 어디서 가능해질까?

작업 순서를 유지하고 작업을 쪼개지 않습니다. 양의 작업량을 D일 이내에 처리하는 최소 하루 용량 C를 찾습니다.

불변식 · 최소 가능한 용량은 [lo, hi] 안에 있습니다.용량을 늘려도 필요한 날짜 수는 늘지 않습니다. 가능한 mid는 답 후보로 남기고, 불가능한 mid 이하는 버립니다.

왜 하루를 최대한 채워도 될까요?

양의 작업을 순서대로 처리할 때, 더 일찍 하루를 끝내는 방법보다 현재 용량 안에서 최대한 진행하는 방법이 처리한 접두사를 짧게 만들지 않습니다. 날짜마다 이를 반복하면 최소 필요 날짜를 얻습니다. 작업 재정렬이나 분할을 허용하는 문제에는 같은 모델을 그대로 적용하지 않습니다.

C++17 · 판정 함수에서 정답까지
bool feasible(const vector<long long>& a, int days, long long cap) {
    int used = 1;
    long long load = 0;
    for (long long x : a) {
        if (x > cap) return false; // 하나의 작업도 쪼갤 수 없음
        if (load > cap - x) { ++used; load = 0; }
        load += x;
    }
    return used <= days;
}
long long minimumCapacity(const vector<long long>& a, int days) {
    // a는 비어 있지 않은 양수 배열, days >= 1, sum(a)는 long long 범위
    long long lo = *max_element(a.begin(), a.end());
    long long hi = accumulate(a.begin(), a.end(), 0LL);
    while (lo < hi) {
        long long mid = lo + (hi - lo) / 2;
        if (feasible(a, days, mid)) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}

필요 헤더: vector, algorithm, numeric · std 이름 공간 사용. 시간 O(N log R), 공간 O(1), R = sum(a) − max(a) + 1.

02 / FRONTIER & PATH

도착하기 전, 큐에는 무엇이 남을까?

상하좌우 이동 비용은 모두 1입니다. 왼쪽 위 S에서 오른쪽 아래 T까지 최소 이동 횟수와 경로 하나를 찾습니다.

불변식 · 처음 큐에 넣을 때 거리와 부모를 기록합니다.큐에는 먼저 발견한 칸부터 들어 있습니다. 같은 칸을 다시 넣지 않으며, 방문 거리와 최종 경로는 서로 다른 정보입니다.

아래 칸을 누르면 벽/통로가 바뀌며 첫 단계로 돌아갑니다. S와 T는 고정입니다. 이웃 순서는 위 → 오른쪽 → 아래 → 왼쪽입니다.

방문 배열을 좌표만으로 만들면 언제 틀릴까요?

열쇠 보유 여부나 벽을 부술 수 있는 남은 횟수가 다음 이동을 바꾸면, 같은 좌표도 서로 다른 상태입니다. 그때는 dist[행][열][상태]가 필요합니다. 간선 비용이 서로 다르면 이 BFS의 거리 확정 근거도 다시 검토해야 합니다.

03 / CANDIDATES & RECONSTRUCTION

tails를 그대로 답으로 쓰면 왜 틀릴까?

엄격 증가 부분수열을 찾습니다. 길이별 최소 끝값 후보와 실제 원본 인덱스의 연결을 구분하세요.

불변식 · tails[k]는 길이 k+1인 후보의 최소 끝값입니다.교체는 더 유리한 끝값을 남깁니다. 실제 수열은 각 원소를 처리할 때 기록한 parent 인덱스를 따라 복원합니다.

upper_bound로 바꾸면 어떤 문제를 풀게 될까요?

[2,2,2]에서 lower_bound는 첫 2의 위치를 계속 교체하므로 엄격 증가 길이는 1입니다. upper_bound를 쓰면 같은 값 뒤에 추가하여 비감소 부분수열 길이 3을 구합니다. 비교 조건 하나가 문제 정의를 바꿉니다.
