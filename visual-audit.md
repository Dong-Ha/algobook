## Reusable renderer findings

The walkthrough renderer in `docs/visuals.js` supports rows, grids, generic graph SVG, and interval timelines. The separate interactive LAB in `docs/app.js` supports graph traversal with stack/queue state, a trie SVG, and array traces for sorting, prefix sums, two pointers, binary search, backtracking, and coin DP. These are distinct rendering paths: LAB pointer/frontier labels do not automatically apply to static walkthrough data.

The proposed shared schema can reuse `sequence`, `mapping`, `graph`, `tree`, `timeline`, `dependency`, `bitset`, `frontier`, `range-search`, `pointers`, and `state-space` families. High-priority gaps are range/pointer walkthroughs, DP dependencies, priority frontiers, stack pops, Fenwick/segment paths, and LCA jumps.

## Implemented design

The UI controls and static Vanilla JS delivery remain unchanged. Each step now declares a `renderer` teaching family, and each row declares a semantic `type`: `array`, `state`, `sequence`, `stack`, `queue`, or `bitset`. Only arrays and bitsets display position labels. Explicit labels distinguish BIT indices, vertices, amounts, LIS lengths, and value domains.

Shared primitives in `docs/visuals.js` render graphs/trees, indexed sequences with pointers/ranges, frontier containers, grids, timelines, and directed transition flows. The LAB and walkthrough share graph/trie adapters, pointer/range sequences, DP dependency rows, and transition primitives; `AlgoEngine` only adds the old and candidate coin-DP values to its existing trace.

Priority structures now include two-pointer decisions, binary-search elimination previews, DP dependencies, choose/skip state-space branches, DFS/BFS frontier and completion roles, Trie character paths, DSU forests/root lookup and path compression, Dijkstra priority/stale candidates, meeting selection/conflicts, segment query cover/update ancestors, BIT coverage/lowbit paths, stack pop-to-answer links, LIS replacement versus append, sweep event order, LCS source cells, LCA query/lifting paths, and labeled ON/OFF bits. Concept examples show ID mappings, affected windows, candidate checks, witness paths, path bottlenecks, resource feasibility, and cumulative-count descent.

Wide sequences and trees scroll within their scene; graph regions are keyboard focusable and narrow screens display a horizontal navigation hint. Dependency uses a dashed outline; pending elimination uses hatching; excluded states are muted. Legends depend on the displayed roles, and never advertise 0-based positions for a scalar, queue, graph, or tree alone.

Validation covers all 45 chapters, 253 walkthrough states, engine example outputs, drawn tree sums/update paths, lowbit edges, lifting jumps, bit positions, and stack transitions. Browser checks cover desktop and 390px layouts and both sets of existing controls. The required four Node commands are runnable separately.
